# 逻辑推理出题模型 V2

更新时间：2026-08-30

## 1. 目标与边界

逻辑模型 V2 用于统一港研通的逻辑推理分类、命题提示词、机器校验和人工审核口径。它先服务于现有题库审计与在线 AI 专项出题，后续才用于缺口驱动的新题扩充。

本阶段只做以下工作：

- 用 2025 年真题建立题型、任务、难度和干扰项校准卡。
- 统一逻辑推理的数据库分类及历史别名。
- 为在线生成增加逻辑专用提示词、形式化规格、唯一答案校验和失败重试。
- 对现有题库做只读审计并给出修复分级。

本阶段不生成正式题库批次，不执行 dry-run，不导入题目，不修改数据库。

本地正式逻辑题库固定使用 `data/z001_logic_active_snapshot.json`。该文件由
`scripts/sync_logic_active_snapshot.py` 从线上 `subject=逻辑推理、status=active`
只读导出，并以题目 ID 和完整内容摘要校验。旧生成批次、原始抽取题和未上线候选题
不再计入本地正式题库。

## 2. 2025 年真题校准结论

校准范围为逻辑推理第 56—70 题，共 15 题。题型结构如下：

- 综合推理、符号匹配、分配、方阵和排班：7 题。
- 加强、假设、解释和削弱：4 题。
- 条件推理、量词集合和论证形式相似：4 题。
- 64—65、69—70 使用共享题干；67 为 5×5 方阵图片题。
- 本套真题没有单纯考查“概念种类、定义、划分”的识记题。

附件答案不能直接视为训练金标准。独立核验发现：

- 第 56 题附件缺失答案，题面推断高概率为 C。
- 第 60、64、65、67、69 题的附件答案与题面求解结果冲突。
- 其余 9 题与独立核验一致。

所有缺失或冲突题统一标为 `manual_review`。在第二来源或人工复核完成前，不把这些题的任何答案写入训练金标准。

机器可读校准卡见 `data/logic_2025_calibration_v2.json`。

## 3. 对外分类统一

`subject` 固定为 `逻辑推理`，`exam_code` 固定为 `Z001`。对外模块统一为四类：

| module | submodule |
| --- | --- |
| 概念 | 概念种类、概念关系、定义、划分 |
| 判断 | 判断种类、判断关系 |
| 推理 | 演绎推理、归纳推理、类比推理、综合推理 |
| 论证 | 加强、削弱、假设、解释、推论、论证结构、谬误识别 |

历史值继续兼容读取，但新识别、新生成和新导入必须转换为上述规范值：

- `概念判断` 根据考点转换为 `概念` 或 `判断`。
- `推理规则` 转换为 `推理`。
- `削弱加强` 转换为 `论证`。
- `支持` 转换为 `加强`，`质疑` 转换为 `削弱`。

数据库分类只表达稳定知识结构。更细的母题、设问任务、形式化条件和干扰项角色放在 V2 审核元数据中，避免继续膨胀 `module/submodule`。

## 4. V2 审核元数据

在线生成的逻辑题必须同时返回 `logic_v2`，该对象只用于生成时校验和审核，不直接写入 `questions` 表。

```json
{
  "logic_v2": {
    "version": "2.0",
    "logic_model": "assignment",
    "question_task": "must_be_true",
    "premise_form": ["每人恰好对应一个值", "若 P 则 Q"],
    "variables": ["甲", "乙"],
    "constraints": ["甲不对应红色"],
    "distractor_types": {
      "B": "把可能成立误当必然成立",
      "C": "遗漏条件",
      "D": "逆命题误用"
    },
    "source_fragment_ids": [],
    "shared_stem_id": null,
    "verification_status": "solver_verified",
    "counterexamples": {
      "B": "存在满足全部条件但 B 不成立的赋值",
      "C": "存在满足全部条件但 C 不成立的赋值",
      "D": "存在满足全部条件但 D 不成立的赋值"
    },
    "difficulty_features": ["条件链长度 3", "需要排除 2 个局部可行解"],
    "formal_spec": {}
  }
}
```

关键字段：

- `logic_model`：母题结构，如 `conditional`、`categorical_quantifier`、`assignment`、`sequencing`、`grouping`、`scheduling`、`grid`、`code_mapping`、`argument_causal`、`formal_similarity`。
- `question_task`：设问任务，如 `must_be_true`、`could_be_true`、`cannot_be_true`、`strengthen`、`weaken`、`assumption`、`explain`、`parallel_reasoning`、`flaw`。
- `premise_form`：自然语言条件对应的标准逻辑形式。
- `distractor_types`：每个错项的错误机制，不能只写“错误项”。
- `verification_status`：结构题使用 `solver_verified`，论证题使用 `rubric_verified`；`manual_review` 不得通过在线自动写入门。
- `counterexamples`：说明每个错项为什么不是最佳答案；结构题优先由求解器生成反例赋值。
- `formal_spec`：有限域结构题的机器可执行规格。

## 5. 命题流水线

```text
资料切片并分配来源 ID
→ 从真题抽取题型卡
→ 规划母题与设问任务
→ 先构造形式化逻辑骨架
→ 求解器验证可满足性和唯一答案
→ 为每个错项生成反例或论证角色说明
→ 再自然语言化题干、选项和解析
→ 检查难度、模板相似和语义重复
→ 人工复核
```

结构题必须“先骨架、后成题”。如果先写自然语言再补形式化规格，很容易出现规格与题面不一致，因此每条约束和每个选项都要保留对应的原文片段用于回查。

论证题暂不伪装成可求解的真假约束。它必须明确：结论、证据、缺口、正确项作用、三个错项的作用或无关性，并通过论证题专用审核量表。

## 6. 质量门

### L0：结构与分类

- 仅允许 A—D 四个非空且互不重复的选项。
- 只有一个答案标签，题型固定为 `single_choice`。
- 分类必须命中统一目录，历史别名只可在识别阶段转换。
- 题干不得出现批次、AI、生成过程、复盘报告或讲义来源等元描述。

### L1：任务与母题一致性

- 题干设问必须能识别为明确任务。
- `question_task`、`logic_model`、`module/submodule` 必须相互匹配。
- 不得把综合推理包装成概念识记题，也不得把假设题笼统归入加强题。

### L2：结构题求解器验证

- 形式化条件至少存在一个可行解。
- `must_be_true`、`could_be_true`、`cannot_be_true` 等任务由全部可行解计算。
- 恰好一个选项满足设问，且与 `answer` 一致。
- 每个错项都保存反例赋值或不可行原因。
- 形式化规格状态空间超过安全上限时进入人工复核，不以抽样结果冒充证明。

### L3：论证题审核

- 明确材料结论、论据和逻辑缺口。
- 正确项必须直接作用于缺口，而非只与主题相关。
- 三个错项分别说明：无关、力度不足、方向相反、重复题干或偷换对象中的哪一种。
- 解析至少说明正确项为何成立，并具体指出两个以上错项为什么不成立。

### L4：题库级检查

- 精确重复、模板换词和高相似题分开统计。
- 难度由条件数、条件链、可行解数量、阅读量和干扰项接近度共同决定，不由模型主观自报。
- 资料片段用于知识与规则依据，真题卡用于题型和难度参照，两者都不能被原样抄入题目。

## 7. 在线生成行为

- 逻辑题使用 V2 专用提示词，其他科目的在线生成逻辑保持原样。
- 模型返回后先走共享质量校验器；失败题不写入数据库。
- 校验失败原因会进入下一轮提示词，最多按既有重试上限重新生成。
- 结构题缺少 `formal_spec`、可行解为 0、答案不唯一或求解答案与声明答案不一致时直接拒收。
- 论证题缺少三项错项角色和反例说明时直接拒收。
- V2 元数据保留在训练会话原始响应中，`questions` 表仍只写当前数据库字段。

## 8. 现有题库审计分级

| 分级 | 含义 |
| --- | --- |
| `keep` | 通过当前静态质量门；不等于已完成人工真值复核 |
| `format_fix` | 分类别名、题型字段、标点或格式可机械修复 |
| `content_fix` | 解析不足或局部措辞需要补强，核心逻辑暂未发现冲突 |
| `rewrite` | 元描述、无效干扰项、模板化或题面质量低，建议重写 |
| `manual_review` | 答案、推导、歧义或形式化一致性存在风险，需要人工复核 |
| `archive_candidate` | 精确重复或严重同质化，建议保留追溯后下架候选 |

审计脚本只输出报告和候选清单，不自动改题、不自动下架、不写数据库。

## 9. 后续新增题的启动条件

只有在现有逻辑题库完成审计、人工复核优先级确认、分类修复策略确认后，才建立缺口矩阵并新增题目。新增顺序应优先补齐真题中占比高而现有题库薄弱的：

1. 条件约束下的综合推理与共享题干题组。
2. 假设、解释、论证结构等任务。
3. 量词集合和形式相似题。
4. 可文本化且能被求解器复算的方阵、排班和分配题。

纯概念识记题不应继续作为大批量扩充的默认方向。
